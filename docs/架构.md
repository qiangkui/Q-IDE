# 架构说明

面向要改代码的人：模块职责、数据流、持久化格式与验证方式。「坑位备忘」的完整清单在 [ROADMAP.md](../ROADMAP.md)，本文件只保留结构性说明。

## 技术栈

| 依赖 | 用途 |
| --- | --- |
| `gpui`（`gpui-pre`） | GPU 加速 UI 框架：窗口、布局、渲染、事件 |
| `gpui-kit` | 在 gpui 之上的组件层：`DockArea`、`Editor`、`Tree`、`Input`、菜单、主题 |
| `gpui-component`（`vendor/gpui-component`，本地补丁） | `gpui-kit` 使用的组件实现；本仓库打了补丁（菜单字号更小、取消斜体；设置项说明文字字号更小），通过 `[patch.crates-io]` 生效 |
| `tree-sitter` / `tree-sitter-rust` | Rust 语法高亮 |
| `encoding_rs` | UTF-8 / UTF-16 / GBK 探测与写回 |
| `lsp-types` | 补全接口使用 LSP 数据类型 |
| `serde_json` | Dock 布局（`DockAreaState`）的序列化 |
| `embed-resource` | 构建时把 `app.rc` / `run.rc` 的图标编进对应 exe |

这是一个**二进制 crate**（没有 `lib.rs`），所有模块都在 `src/main.rs` 里用 `mod` 声明。

## 启动流程

```text
main()                                   // src/main.rs
  startup::parse(args)                   // --help / --version / 待打开的文件与文件夹
  gpui_kit::application().with_assets(...).run
    gpui_kit::init(cx)                   // 注册组件与主题基础
    app::init(cx)                        // 注册 action + 快捷键（KeyBinding）
    SettingsStore::init(cx)              // 全局设置实体
    ThemeStore::init(cx)                 // 读 exe 同目录的 themes.txt（自定义主题）
    theme::apply_from_settings(cx)       // 应用内置或自定义主题
    Layout::load()                       // 读 exe 同目录的 layout.txt
      └ window_bounds → WindowOptions
    gpui_kit::open_window
      window_frame::setup(window, bg)    // Windows 窗口外框、阴影、圆角
      CodeWindow::new(window, cx)        // 主窗口实体
        └ open_startup_paths(...)        // 打开命令行给出的文件（文件夹加进资源管理器）
```

命令行里没有路径时行为与以前完全一致：只按上次保存的布局开窗。

`CodeWindow::new` 负责：建空编辑器、输出日志、Dock 面板（`CodeWindow::register_dock_panels`）、恢复资源管理器根目录与展开状态、恢复打开过的标签与激活项、注册各种观察者（设置变化、编辑器内容变化、窗口矩形变化、每秒自动保存/外部修改检测）。

## 脚本运行与调试

脚本**不在 UI 线程跑**：

```text
UI 线程                                 脚本线程（std::thread）
run_script()                            interpreter::run_with(...)
  ├ 保存当前标签内容                        ├ callback → mpsc::Sender<Line>
  ├ RunOptions { script_path, args }      └ 结束 → Sender<Finished(Result)>
  └ spawn(线程)
spawn_script_events(receiver)  // cx.spawn 异步循环
  ├ try_recv 拉取输出/结束事件 → 输出面板
  └ 调试时按 (is_paused, pause_epoch) 变化拉取快照；
    监视求值走独立轻量通道（一次一条请求）
```

要点：

- 输出通过 `mpsc` 回到 UI 线程写入输出面板；脚本结束时写入用时。
- 脚本线程用 `interpreter::spawn_script_thread` 创建（栈 64 MiB）。标准库默认的 2 MiB 栈在深递归脚本下会
  直接触发栈溢出，整个进程被终止且界面上没有任何提示；`max_depth` 默认 200，debug 构建每层约 80 KB。
- 停止脚本 = 置 `Arc<AtomicBool>` 中断标志；解释器在语句边界检查，`MsgBox`/`InputBox` 的自建消息循环也会检查并立刻关闭窗口。
- 调试通过 `Arc<DebugControl>` 双向通信：解释器在每条语句前查询暂停请求；暂停时把行号与变量快照写进控制块，UI 侧轮询取走。
- 监视求值发生在解释器线程停在 `before_line` 时的「借出」时间片里：求值前放开调试锁，并用 `Runtime::evaluating` 让表达式内部跳过暂停检查，否则会自锁。条件断点走同一条路径（`DebugQuery::Condition`）。

## AI 对话

代码按「界面 / 网络 / 协议 / 工具」分成四块，`client`、`stream`、`tools` 都不依赖界面代码，方便整体移植：

| 模块 | 职责 |
| --- | --- |
| `ai/panel.rs` | GPUI 面板：气泡渲染、工具活动与写入/执行确认、代码块折叠/展开/复制、输入、滚动 |
| `ai/client.rs` | DeepSeek 网络层：地址解析、请求体（含 tools）、WinHTTP 流式请求（阻塞） |
| `ai/stream.rs` | SSE 增量解析：字节流 → `Delta` / `ToolCalls` / `Done` / `Error` |
| `ai/tools.rs` | 工具层：工具清单（JSON Schema）+ 把一次调用算成只读结果、待写入文件或主窗口操作 |
| `ai/markdown.rs` | 极简 Markdown 分段：说明文字 / 围栏代码块 |

```text
UI 线程                                         后台线程
AiPanel::send()                                 client::ask_stream(&request, on_event)
  ├ 从凭据管理器读密钥、从设置读地址/模型            └ WinHTTP: POST /chat/completions
  ├ 追加用户消息 + 一条空的助手消息                      (stream=true, tools=[...])
  ├ spawn(线程) ──mpsc(StreamEvent)──►            文本与工具调用片段分别解出来
  └ cx.spawn_in 每 40ms 批量取走 → 追加/累积 → 通知界面

finish_turn() ─┬─ 没有工具调用 → 结束
               └─ 有工具调用 → process_tools()
                                 ├ 只读工具 → 结果作为 role:"tool" 消息 → 再发一轮
                                 ├ 写文件 · Ask 模式 → 弹确认卡片 → 同意/拒绝 → 再发一轮
                                 └ 写文件 · Auto 模式 → 直接写盘 → 再发一轮
                                 ├ 脚本执行 · Ask 模式 → 弹确认卡片 → 同意/拒绝 → 再发一轮
                                 └ 脚本执行 · Auto 模式 → 主窗口执行 → 再发一轮
```

要点：

- 增量先攒在 `buffered` 里，每 40ms 一次性写进消息再 `notify`，避免每个字触发一次重绘；工具调用的 `arguments` 会按 `index` 累积成完整 JSON。
- 回复先用 `ai/markdown::split` 切开：说明文字交给 `TextView` 按 Markdown 渲染（可拖选、`Ctrl+C` 复制）；代码块用 `TextViewStyle::code_block` 把底色压暗、加边框圆角。默认只取前 5 行，`Clipboard`、「写入」、「展开/收起」浮在代码块右上角。
- 固定规则：程序目录下的 `ai-rules/`（启动时补齐默认文件，不覆盖用户修改）。`common.md` 总是加载，再按当前文件语言加载 `<语言>.md`（VB 是 `vb.md`，没有对应文件就 `default.md`）；每次请求重新读取，改完下一条消息生效。环境变量 `QIDE_AI_RULES_DIR` 可以改用其它目录。拼接由 `client::request_body_for` 负责。
- 上下文：`client::file_context` 把当前打开文件的路径和内容拼成一段文字，接在系统提示后面；超过 4 万字符时在**整行末尾**截断，并写明「只带了前 N 个字符、全文共 M 个字符、后面的用 `read_file` 按行读取」。
- 长度控制：`client::request_body` 按 `REQUEST_CHAR_BUDGET`（7.2 万字符，折算后仍在 DeepSeek 64K token 窗口内）先扣掉系统提示与文件上下文，剩下的给对话历史。超了就 `client::fit_history` 处理：**只在用户消息处整条丢弃**最早的对话（`assistant(tool_calls)` 与它的 `tool` 结果因此不会被拆开），仍然超就把最长的几条消息截一半并加「内容过长，已截断」标记；裁剪发生后系统提示末尾会补一句「更早的 N 条对话已省略 / M 条过长的内容已截断」，让模型知道自己看到的上下文不完整。面板里显示的历史始终是完整原文，只有发给接口的那一份会被裁剪。
- 工具：`tools::plan` 解析模型调用——`read_file` / `list_files` / `check_syntax` / `read_output` / `get_debug_state` 返回文本，`replace_in_file` / `write_file` 返回「要写入的完整内容」，运行、调试、断点和监视工具转换成 `AppAction` 交由主窗口执行；路径经 `tools::resolve` 规整，逃出项目根目录一律拒绝。调试状态提供活动 VB 文件的断点、当前暂停行、调用栈、可见变量及监视结果。
- 交互方式（`settings::AiApproval`，存 `ai_approval`）：`Ask`（默认）遇到写操作或启动/继续/单步执行脚本时先弹确认卡片；`Auto` 自动写盘或执行，只在对话里留一行工具记录。断点、监视与状态查询不执行脚本，不额外弹确认。切换入口在面板底栏（输入框下方）的「执行前确认 / 全部允许」按钮，点开是下拉菜单；旁边的「6 轮 / 12 轮 / 一直执行」按钮对应 `settings::AiRoundLimit`（存 `ai_round_limit`），控制一次提问里最多连续执行多少轮工具调用；再旁边的「模型」按钮列出 `settings::AI_MODEL_OPTIONS`，当前值打勾，若设置里填了列表外的模型会额外显示一条「（自定义）」。按钮都写回 `SettingsStore`，界面靠设置变更通知重绘。
- 写盘由界面层执行：`CodeWindow::write_ai_file`（`app/ai.rs`）——已打开的标签 `editor.set_value` 后按原编码保存，没打开的先写磁盘再 `open_file`，随后刷新大纲/诊断/资源管理器并写输出日志。代码块上的「写入」按钮走同一条路径（`apply_ai_code` 弹路径输入框确认目标）。
- **写盘不能在 AI 面板自己的 `update` 里做**：`AiPanel::spawn_write` 用 `cx.spawn_in` 起一个新任务，先 `app.update_in` 让主窗口落盘，再回到面板里续上工具循环。原因：`write_ai_file` 打开新文件时会触发 `save_layout`，而保存布局要 `dump` Dock 里的每个面板实体（包含 AI 面板本身），在面板更新期间被读取会直接触发 GPUI 的 `cannot read ... while it is already being updated` panic（「全部允许」模式一度因此崩溃）。写盘期间 `pending` 置真，避免用户插话打乱消息顺序。
- 防死循环与停止：`settings::AiRoundLimit` 限制连续工具轮数（默认 6 轮，可切 12 轮或一直执行），`AiPanel::run_turn` 在开新请求前检查 `reached()`。底栏「发送」旁边的「停止」置 `Arc<AtomicBool>` 中断标志，网络层在每个数据块之间检查，界面再用 `request_id` 作废旧请求；`stop()` 会给还没拿到结果的工具调用补一条「已停止」结果，保证历史仍符合接口的 tool-call 协议。「新建对话」与「清空」也会取消当前请求（前者还会清掉输入框并把焦点放回输入框）。
- 模型能力：`tools::model_supports_tools` 判断要不要带 `tools`——`deepseek-reasoner` 不支持函数调用，`tools::tools_for_model` 对它返回空数组，请求里就没有 `tools` / `tool_choice`，只当普通聊天（不会改文件）。
- 请求里带着密钥，`client::ChatRequest` 故意不实现 `Debug`；`Authorization` 头的宽字符缓冲区发完立刻清零；错误信息只带 Windows 错误码或服务端返回的文字。
- SSE 解析按字节缓冲：网络可能在半个 JSON、半个汉字处切断，只有凑齐一整行才解析。
- `request_id` 用来作废过期回复：点「新建对话」或「清空」后旧请求的增量会被丢弃。
- 失败时如果一条增量都没收到，就把占位的空助手消息删掉，只在面板里留错误说明。
- 栈空间：GPUI 按元素树递归绘制界面，主窗口层级较深；AI 回复里的 `TextView`（Markdown）在最深处还会占一层很大的栈帧。默认 1MB 的主线程栈在渲染对话消息时会溢出（进程以 `0xc000041d` 退出），因此 `build.rs` 通过链接参数把 Windows 主线程栈保留大小提高到 8MB。

## 持久化

单一的布局/会话/设置文件：可执行文件同目录的 `layout.txt`（`layout::path()`）；该目录不可写（如装在 `Program Files`）时退回 `%APPDATA%\gpui-first\layout.txt`，旧版本的该文件会在首次启动时自动搬到 exe 旁边并删除。格式是逐行 `键=值`，值做百分号转义，未知键与坏行直接忽略。

| 键 | 含义 |
| --- | --- |
| `layout_version` | Dock 布局版本（当前 2）；版本不符时丢弃 `dock_state` 并重建默认布局，其它键保留 |
| `dock_state` | `DockAreaState` 的 JSON，保存用户拖动/拆分后的面板结构 |
| `left_panel` / `right_panel` | 左右两侧栏各显示哪个面板（`explorer` / `outline` / `search` / `ai`，空值表示该侧不显示） |
| `explorer_width` / `outline_width` / `search_width` / `ai_width` / `output_height` | 面板尺寸 |
| `show_explorer` / `show_outline` / `show_search` / `show_ai` / `show_output` / `show_status_bar` | 面板开关（前四个由左右槽位推导，仅用于阅读与旧版本兼容） |
| `theme` | 内置 `dark` / `light`，或自定义主题名（见 `themes.txt`） |
| `roots` / `root=dir:...` / `expanded` | 资源管理器根目录与展开的文件夹 |
| `breakpoint` / `breakpoint_condition` | 断点与条件断点（按文件路径） |
| `recent` / `open` / `active` | 最近打开（最多 10）、上次的标签（最多 40）与激活项 |
| `script_args` / `watch` | 运行参数、监视表达式 |
| `window_bounds` | 上次窗口位置与大小（逻辑像素），数据不合理时忽略 |
| `settings_size` | 设置窗口上次的宽高（逻辑像素）；太小或数据不合理时忽略 |
| `editor_*` / `syntax_*` / `output_*` | 编辑器、语法分析、输出面板设置 |
| `ai_base_url` / `ai_model` / `ai_approval` / `ai_round_limit` / `ai_font_size` | AI 接口地址、模型名（默认 `https://api.deepseek.com`、`deepseek-chat`）、交互方式（`ask` 每次写入前确认 / `auto` 自动允许所有操作）、工具轮数（`6` 默认 / `12` / `unlimited` 一直执行）与对话区字号（默认 12，范围 8–32 像素） |

**API Key 不写进 `layout.txt`**：DeepSeek 的密钥只存进 Windows 凭据管理器（目标名 `Q-IDE/DeepSeek API Key`，见 `secret_store.rs`），界面上始终遮罩显示，日志、输出面板与 `Debug` 输出都不包含它；清空输入框或点「清除」即删除凭据。

写入时机：设置变化（`sync_settings` 里顺手 `save_layout`）、面板/标签/断点变化、窗口矩形变化（每秒检查）、关闭窗口。

自定义主题单独放在 exe 同目录的 `themes.txt`（`custom_theme::FILE_NAME`），与 `layout.txt` 一样是逐行 `键=值`：

```text
theme=深蓝
base=dark
window_bg=#0B1A2B
sidebar_bg=#10233A
```

- `base` 取 `dark` / `light`，没写出来的颜色都取自这套内置配色，所以手工只改几个键也能用；
- 可编辑的键见 `custom_theme::COLORS`（窗口/活动栏/侧栏/内容区底色、选中色、正文与次要文字、选区、分隔线、文件夹与文件图标）；
- 选中色同时决定菜单选中与设置导航的底色，正文文字一次设置标题、菜单、侧栏与标签；
- 只写 `#RRGGBB` 的选区/分隔线会补上基础配色的透明度，写 `#RRGGBBAA` 则按给定透明度渲染；
- 设置窗口「主题」页：内置主题只读；已保存主题的改名/改色直接替换原条目（改名时删掉旧名字）；「新建主题」以当前配色为底、名字留空。改动即时写盘，同名主题覆盖，`dark` / `light` 是保留名。

## 线程与性能约束

- 项目内搜索、跨文件替换、脚本执行都在后台线程；UI 只做渲染与事件派发。
- 搜索有三道预算：单文件 2 MiB、单次总计 32 MiB、最多 500 处命中，状态行显示进度，新搜索会取消在途搜索。
- **在实体观察者里设置装饰必须先判断是否变化**：`RangeDecorationCollection::set` 每次都会 `notify`，无条件设置会造成「启动即 100% CPU」的自唤醒死循环（`CodeWindow::bracket_pairs` 就是为此存在）。
- 调试快照可能几 MB，只在 `(is_paused, pause_epoch)` 变化时克隆，避免每 40 ms 复制一次导致界面卡顿。

## 测试与验证

```powershell
cargo build
cargo test                # 当前 360 passed / 5 ignored
cargo clippy --all-targets
```

- 测试按模块放在 crate 级文件（`src/xxx_tests.rs`），在 `src/main.rs` 里注册；写在模块内部的 `#[cfg(test)] mod tests` 会触发 rustc 的宏展开递归上限。
- 持久化、模型与纯逻辑（`layout`、`search`、`editing`、`workspace`、`explorer`、`outline`、`encoding`、解释器各层）都有单元测试；纯渲染分支不写测试。
- 界面与交互效果由人工验证：不要用截图或模拟鼠标键盘去点界面。

## 环境与文件约束

- 源码为 UTF-8。**不要**用 Windows PowerShell 5.1 的 `Get-Content` / `Set-Content` / `Out-File` 读写源码：前者按 GBK 解码会破坏中文，`-Encoding utf8` 会写入 BOM。
- 屏幕 DPI 125%（窗口 DPI 120），涉及像素坐标时按物理像素换算。
